# Таблицы и типы данных

[Главная](index.md) · [English](../eng/tables.md)

## Создание таблиц

Таблица создаётся методом `create_table(table_name, *colums, flexible=False)`.

```python
db.create_table(
    "players",
    ("p", "id", int),
    ("un", "login", str),
    ("i", "level", int),
)
```

Каждая колонка задаётся кортежем `(flags, name, type)`: флаги, имя и тип Python. Тип можно опустить - тогда колонка будет создана без объявленного типа SQLite.

```python
db.create_table("events", (0, "payload"))
```

**Важно:** если таблица с таким именем уже существует, `create_table()` ничего не меняет. Новые колонки, типы, ограничения и индексы из изменённого объявления **не применяются**. Это не метод миграции схемы.

## Флаги колонок

Флаги можно передавать строкой в любом порядке и регистре. Для колонки без флагов используй `0` или `""`.

| Флаг | Действие |
|---|---|
| `i` | Создать индекс по колонке. |
| `n` | Запретить `NULL` (`NOT NULL`). |
| `p` | Назначить первичный ключ (`PRIMARY KEY`). |
| `u` | Добавить ограничение уникальности (`UNIQUE`). |

Например, `("un", "login", str)` объявляет обязательный уникальный логин.

При создании таблицы LiteCrate не добавляет отдельный индекс `i`, если для той же колонки уже задано `u` или `p`. Подробнее: [Индексы](indexes.md).

**Нюанс SQLite:** у обычной таблицы нецелочисленный первичный ключ не всегда запрещает `NULL`. Если поле обязательно, явно добавь `n`, например `("pn", "code", str)`. Целочисленный `("p", "id", int)` используется как `INTEGER PRIMARY KEY`, и SQLite может назначать такой идентификатор автоматически.

## Типы данных

| Тип Python | Тип SQLite |
|---|---|
| `int`, `bool` | `INTEGER` |
| `float` | `REAL` |
| `str` | `TEXT` |
| `bytes` | `BLOB` |
| `dict`, `list` | `TEXT` (JSON) |
| `None` или пропущенный тип | Без объявленного типа |

Колонки `dict` и `list` автоматически преобразуются в JSON при записи и восстанавливаются при чтении. Колонки `bool` возвращают `True` или `False`. Для остальных типов действуют правила приведения типов SQLite.

Если нет ограничения `NOT NULL`, можно передавать `None`, в том числе в колонки `dict` и `list`.

## Управление таблицами

| Метод | Действие |
|---|---|
| `get_tables(include_internal=False)` | Получить список таблиц в алфавитном порядке. |
| `rename_table(target, value)` | Переименовать таблицу. |
| `delete_table(target)` | Удалить таблицу, если она существует. |

```python
db.rename_table("players", "members")
print(db.get_tables())
# ['members']

db.delete_table("members")
```

По умолчанию `get_tables()` скрывает служебные таблицы; `include_internal=True` включает их в результат. При переименовании LiteCrate также переносит свои метаданные и переименовывает индексы, созданные по его схеме именования.

## Метаданные

LiteCrate хранит сведения о типах объявленных колонок в служебной таблице `_litecrate_meta`. Это позволяет корректно читать `bool`, `dict` и `list` после повторного открытия базы.

Имя `_litecrate_meta` зарезервировано для таблицы метаданных. Колонка `_data` предназначена для [гибких полей](flexible.md) и также зарезервирована.

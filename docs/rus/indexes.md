# Индексы

[Главная](index.md) · [Таблицы и типы данных](tables.md)

## Индексы при создании таблицы

Флаг `i` создаёт индекс по колонке:

```python
db.create_table(
    "players",
    ("p", "id", int),
    ("un", "login", str),
    ("i", "level", int),
)
```

При этом `create_table()` избегает избыточных индексов: если на той же колонке есть `PRIMARY KEY` (`p`) или `UNIQUE` (`u`), отдельный индекс для `i` не создаётся. Например, `"ui"` не создаёт дополнительный неуникальный индекс.

Эта проверка применяется **только при создании таблицы**. Повторный вызов `create_table()` для существующей таблицы не добавляет новых индексов, даже если её объявление изменилось.

## Управление индексами

| Метод | Действие |
|---|---|
| `create_index(table_name, column_name)` | Создать индекс по колонке. |
| `remove_index(table_name, column_name)` | Удалить индекс с именем, генерируемым LiteCrate; отсутствие индекса допускается. |
| `get_table_indexes(table_name)` | Получить отсортированный список имён индексов таблицы. |

```python
db.create_index("players", "level")

print(db.get_table_indexes("players"))
# ['idx_78d030432d37cc35775d8d2e012ac858']

db.remove_index("players", "level")
```

**Важно:** `create_index()` не проверяет, нужен ли индекс. Он может создать индекс даже для колонки, которая уже индексируется через `UNIQUE` или `PRIMARY KEY`.

Кроме того, `create_index()` использует обычный `CREATE INDEX`: если индекс с генерируемым именем уже существует, SQLite вернёт ошибку. В отличие от `remove_index()`, этот вызов не предназначен для безошибочного повторения.

`get_table_indexes()` не показывает автоматические индексы SQLite, создаваемые для ограничений `UNIQUE` и `PRIMARY KEY`. Удаление индекса LiteCrate не отменяет сами эти ограничения.

Если схема известна заранее, обычно удобнее объявить индекс флагом `i` в `create_table()`.

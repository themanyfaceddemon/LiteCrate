# Гибкие поля и JSON

[Главная](index.md) · [English](../eng/flexible.md)

Гибкие таблицы позволяют хранить записи с произвольным набором полей без необходимости изменять структуру таблицы.

## Создание гибкой таблицы

Для включения гибких полей используется параметр `flexible=True`:

```python
db.create_table(
    "players",
    ("un", "login", str),
    flexible=True,
)
```

Объявленные поля хранятся в обычных колонках SQLite, а дополнительные - в JSON внутри служебной колонки `_data`.

## Работа с гибкими полями

Добавление и чтение гибких полей ничем не отличается от работы с обычными колонками.

```python
db.insert(
    "players",
    login="ada",
    level=5,
    settings={"theme": "dark", "sound": True},
)

player = db.select_one("players", "login = ?", "ada")
print(player)
# {
#     'login': 'ada',
#     'level': 5,
#     'settings': {'theme': 'dark', 'sound': True}
# }
```

LiteCrate автоматически объединяет данные из обычных колонок и JSON. Служебная колонка `_data` в результате не отображается.

### Обновление полей

Метод `update()` позволяет изменять существующие поля и добавлять новые, не затрагивая остальные значения записи.

При этом словари и списки **заменяются целиком**, а не объединяются с прежним содержимым.

```python
db.update(
    "players",
    "login = ?",
    "ada",
    level=10,
    nickname="Pilot",
    settings={"theme": "light"},
)

player = db.select_one("players", "login = ?", "ada")
print(player)
# {
#     'login': 'ada',
#     'level': 10,
#     'settings': {'theme': 'light'},
#     'nickname': 'Pilot'
# }
```

В примере поле `nickname` было создано, `level` изменено, а словарь `settings` полностью заменён. Поэтому прежний ключ `sound` отсутствует.

### Неизвестные поля

В гибком режиме дополнительные поля создаются автоматически. Это относится и к ошибкам в их названиях.

```python
db.update("players", "login = ?", "ada", levle=20)

player = db.select_one("players", "login = ?", "ada")

print(player["level"])
# 10

print(player["levle"])
# 20
```

Опечатка `levle` не вызвала исключения: вместо изменения `level` библиотека создала новое поле.

## Поиск по гибким полям

LiteCrate позволяет использовать обычные SQL-условия для поиска по дополнительным полям.

```python
db.select("players", "level >= ?", 5)
db.count("players", "nickname IS NOT NULL")
```

Библиотека автоматически определяет, какие поля являются обычными колонками, а какие хранятся в JSON.

### Вложенные значения

Для поиска внутри вложенных JSON-объектов можно использовать функцию SQLite `json_extract()`:

```python
db.select(
    "players",
    "json_extract(_data, '$.settings.theme') = ?",
    "light",
)
```

Однако прямое обращение к `_data` не рекомендуется, поскольку привязывает код к внутренней структуре хранения LiteCrate.

## Типы данных и ограничения

Дополнительные поля поддерживают JSON-совместимые значения: строки, конечные числа, `bool`, `None`, списки и словари со строковыми ключами.

При работе с гибкими полями следует учитывать следующие особенности:

- **`None` и отсутствующие поля.** Значение `None` сохраняется как JSON `null`. Отсутствующие поля не включаются в возвращаемый словарь. Условие `field IS NULL` может совпасть с обоими случаями.
- **Индексы и ограничения.** По гибкому полю верхнего уровня можно создать [индекс](indexes.md#индексы-по-гибким-полям). Для ограничений `UNIQUE` и `NOT NULL` используются обычные колонки.
- **Двоичные данные.** Тип `bytes` не поддерживается в JSON. Для его хранения следует использовать отдельную колонку.

Подробнее об объявлении колонок: [Таблицы и типы данных](tables.md).
